# Reproducibility Statement

This document records exactly how every number, figure, table and PDF in this package was
produced, what environment was used, and how an independent reader can regenerate the whole
chain from source.

---

## 3. Numerical settings that matter for reproduction

These are the settings that determine the reported digits; they are also written into
`run_manifest.json` by every full run.

| Setting | Value |
| --- | --- |
| Characteristic time | $\tau_\Delta = 0.04$ |
| Baseline constitutive parameters | $\tau_q = \kappa^2 = 0.02$, $\alpha_0 = 1.0$ |
| Resonance definition | $B \equiv \kappa^2/(\alpha_0\tau_q) = 1$ |
| PDE mesh sizes | $N_x \in \{100, 200, 400, 800\}$ |
| PDE time integrator | BDF, rtol $10^{-10}$, atol $10^{-12}$ |
| Laplace inversion methods | de Hoog (quotient-difference, Padé accelerated) and modified Talbot contour |
| Working precisions | 30–80 digits for inversion audits; 40 digits for sensitivity Jacobians; 50 digits for field invariance |
| Sensitivity Jacobian | **analytic differentiation** (`mpmath.diff`) of the closed-form transfer function, degree 20, 40 digits |
| Independent FD channel | central differences, relative step $h_{\rm rel}=10^{-4}$ (used only to quantify the truncation floor) |
| Fisher matrix | $\bm{F}=\sigma_n^{-2}\bm{J}^\top\bm{J}$ with $\bm{J}=[\bm{J}_{\tau_q},\bm{J}_{\kappa^2},\bm{J}_{Bi}]$ |
| Near-resonance CRLB | ordinary inverse at $B=0.99$ |
| Resonance CRLB | Moore–Penrose pseudoinverse at $B=1$ (rcond $10^{-12}$) |
| Condition numbers at $B=1$ | analytical value is infinite; stored values are the IEEE 754 double-precision evaluation floor, flagged by `cond_F_at_numerical_floor` |
| Noise levels audited | $\sigma_n \in \{0.1\%, 0.5\%, 1.0\%\}$ |
| Temporal sampling audited | $N_t \in \{10, 50, 100\}$ |
| Sensor configurations audited | rear-face only; front + rear; five-station multi-location |

## 5. Byte-level reproduction protocol

The pipeline is deterministic: no random numbers, no multi-threaded reductions with
non-deterministic summation order, and no wall-clock-dependent output (other than recorded
timings and PDF creation timestamps). The protocol used to certify this package was:

1. Archive the shipped artifacts: `md5sum data/*.csv figures/*.pdf > before.md5`.
2. Re-run `python3 program/reproduce_all.py` from the package root.
3. Archive again: `md5sum data/*.csv figures/*.pdf > after.md5`.
4. Compare with `diff before.md5 after.md5`.

Result of the certification run (2026-09-28): **18 of the 19 CSV datasets regenerate
byte-for-byte.** `data/mesh_convergence.csv` is scientifically deterministic except for its
wall-clock `runtime_sec` field, which records the measured solve time of each mesh
refinement and therefore varies between runs; every other column of that file (grid spacing,
$L^\infty$ and $L_2$ errors, observed convergence order) regenerates exactly. All 10 figure
PDFs likewise regenerate byte-for-byte, with the sole exception of the PDF `/CreationDate`
metadata timestamp. Accordingly, this package does **not** claim bit-for-bit identity for the
CSV archive as a whole. Any change to a *scientific* value therefore indicates a code change,
not numerical noise, and every such change is documented in
`CHANGELOG_FINAL_REPAIR.md`.

The `runtime_sec` column is retained deliberately: it is a genuine performance measurement of
the conservative-FVM solver at each mesh resolution, and removing it would discard
information without any scientific benefit.

A second, independent determinism check was run **from inside this delivered package**
(`python3 program/plot_figures.py`): all 10 figure PDFs came out identical to the shipped
ones once the creation timestamp is stripped (10/10), and
`python3 program/make_supplementary.py` regenerated `supplementary/supplementary_material.tex`
byte-for-byte from the archived CSVs.

## 7. Manuscript build

**Required tools:** a TeX installation providing both `pdflatex` and `bibtex` (on
Debian/Ubuntu: `texlive-latex-base texlive-latex-recommended texlive-fonts-recommended
texlive-latex-extra`; MacTeX and MiKTeX include both).

```bash
cd manuscript
bash compile.sh          # pdflatex → bibtex → pdflatex → pdflatex
```

`compile.sh` verifies `command -v pdflatex` and `command -v bibtex` first. If either is
missing it prints the installation instructions and exits with status 1 **without producing
or modifying any PDF**; it never falls back to a previously generated `main.pdf`. This was
tested in the release environment with `pdflatex` absent, with `bibtex` absent, and with the
full toolchain present.

The shipped build is clean: **47 pages, 64 bibliography entries, 0 undefined references,
0 overfull boxes** (built with pdfTeX 3.141592653-2.6-1.40.26 and BibTeX 0.99d). A
pre-compiled `main.bbl` is included so that a `pdflatex`-only build (for example in a
restricted build environment) also resolves the bibliography.

For the supplementary material:

```bash
cd supplementary
pdflatex supplementary_material.tex
pdflatex supplementary_material.tex      # second pass resolves the internal references
```

The supplementary source is regenerated from the archived datasets by
`python3 program/make_supplementary.py`, so the tables can never drift from the CSVs.

For Overleaf: upload the contents of `overleaf/` into a new blank project and press
**Recompile**. The Overleaf mirror is byte-identical to `manuscript/` for every source file.

## 8. What is *not* claimed

- No physical experiment was performed and no measured thermogram is reported.
- No public archive or DOI for the data is claimed in the manuscript; the datasets are
  provided with the submission materials and will be deposited publicly upon acceptance.
- No bibliographic entry, DOI, author, or citation is fabricated; all 64 references were
  re-verified against the Crossref metadata API in September 2026.
- The CRLB statements are local bounds for unbiased estimators under an additive
  independent Gaussian noise model; they are not statements about the global behaviour of a
  particular non-linear regression algorithm.
